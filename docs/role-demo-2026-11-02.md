# Local role demonstration — 2 November 2026

The running demo-wsb application passed 18 visitor/account cases across 47 pages
at desktop (1365px) and phone (390px) widths. These are real browser sessions,
server requests, layout checks and permission denials. Page coverage is not proof
of every business workflow, official event rules or production readiness.

## Open or repeat the demonstration

- App: <http://localhost:3100/sign-in>.
- Screenshot walkthrough while its local server runs: <http://localhost:3112>.
- Saved walkthrough: `.workspace/role-demo/index.html`.
- Structured evidence: `.workspace/role-demo/report.json`.
- Repeat the browser demonstration: `npm run demo:roles`.
- Show the browser during the run: set `WSB_DEMO_HEADED=true` first.
- Run one account: set `WSB_DEMO_ACCOUNT=director` (or the exact account key
  from `tests/role-demo-browser.cjs`). Clear it to restore the full run.

Use the shared synthetic password in the ignored `.env.docker` settings. The
walkthrough and report omit credentials and tokens. Each account has an isolated
browser context. The walkthrough provides links and screenshots; it does not
impersonate accounts or bypass sign-in.

## Action verification beyond page coverage

The following independent scenarios passed against the local stack:

- `tests/registration-browser.cjs`: desktop and phone crew creation with a lost
  response and reload/retry; dancer invitation and sign-in return; roster,
  payment reservation/reconciliation, submission and registrar approval. The
  approval scenario injects synthetic audio metadata and does not prove real
  eligibility or consent.
- `tests/verification-browser.cjs`: desktop and phone valid PDF submission,
  lost create/submit/review responses, interrupted-upload resume, private
  review and participant reload recovery.
- `tests/support-browser.cjs`: desktop and phone public/account inquiry forms,
  lost-response replay, private-key recovery, staff replies, account/chapter
  boundaries and support-role finance denial.
- `tests/local-paymongo-browser.cjs`: phone reservation, cancellation, signed
  simulated settlement and reload. No real money moves.
- `tools/test-rehearsal.ps1`: synthetic API role scenarios and persisted-state
  recovery, music upload/correction/review/DJ ZIP, draft-policy checks,
  server-rendered content checks and eight judging-outbox tests. New regressions
  cover HQ root lists/count response shape and check-in candidate denials.
- Rust `verification::document_tests`: valid catalog/page objects survive the
  PDF budget filter; a header-only fake PDF is rejected.

`tests/docker-browser.cjs` also passed at both widths: a real browser saves a
device draft, queues it while disconnected, reconnects for an accepted server
receipt, signs out, and opens the director's result-publication desk. Assignment
desk page coverage is separate; this action case uses the stable synthetic
scorecard directly. It does not verify every paginated assignment interaction.

## Defects corrected during the demonstration

- Rebuilt the stale web image with the required QR dependency and rebuilt the
  API so the running app reflects the current source.
- Replaced fixed sample-event administration links with assigned-event access;
  chapter switching now uses current memberships.
- Preserved HQ sign-in destinations and added server-verified HQ discovery.
- Wrapped long registration identifiers within their phone cards.
- Preserved ordinary PDF objects in the parser callback instead of replacing
  them with null; retained budget validation and strict parsing.
- Recovered a completed review's authorized receipt before attempting a Storage
  read that is intentionally unavailable after completion.
- Routed existing check-in candidate reads through to their authorized handler.
- Accepted the read-only chapter-director row in the staff list while retaining
  the prohibition on director grants/revocation in chapter staff controls.
- Corrected the root collection parent path used by HQ chapter/application lists.
- Rendered numeric HQ aggregate totals instead of passing objects to React.
- Provisioned the missing synthetic PH membership once for the multi-chapter
  account, preserving existing edits and future revocation.
- Cleared the permission-check loading state after sign-out.
- Updated old browser scenarios to follow pagination rather than assume new
  records appear on the first page, and supplied a structurally valid PDF fixture.

## Unfinished scope

The separate role families and production/policy gates in
[the rehearsal runbook](role-workflow-rehearsal.md) and
[open questions](open-questions.md) remain unfinished. This includes verified
guardian authority and actual signing, tickets/VIP, signed/offline admission,
full brackets and advancement, privacy export/deletion, separate publishing and
governance roles, approved event rules and commercial terms, production payment
validation, deployment and operational recovery. The demonstration does not
activate these features or turn proposals into approved rules.
